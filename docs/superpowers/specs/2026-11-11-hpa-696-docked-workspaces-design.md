# HPA-696 — Right-side docked workspaces — Design

**Linear:** https://linear.app/cwchanap/issue/HPA-696/dock-the-panels-on-the-right  
**Repository:** cwchanap/Caelum  
**Baseline:** main at 0168a57d59387286fea0fae8c97495b97efc9a5a (HPA-676 art merged, 2026-11-11)  
**Delivery:** One HPA-696 PR. This draft begins with specification and plan only; implementation and tests belong on this same PR after review. HPA-677 stays a separate task/PR.

## Player outcome

A player can keep every map tile visible and clickable while building infrastructure or composing a line. Build, Lines, Data, and City use one consistent right-side dock. Inspect becomes a small anchored popover, not a second workspace. The Build/route editor visuals use the already delivered Sunny Diorama assets and shared light-theme tokens.

## Current state, verified on main

- **src/App.svelte** renders GameCanvas, Topbar, InspectPanel, CommandPanel, ActionFeedback, and CommandShelf as siblings in one game-workspace. The command destination and route draft are already in the runtime/UI snapshot.
- **src/components/hud/CommandPanel.svelte** wraps a centred overlay; **src/styles.css** positions panels with full-viewport widths, including a special-case right offset for pinned Lines at 1200–1399px. A route editor can still hide map click targets.
- **src/render/boardTransform.ts** is the one transform for WebGPU, hit-testing, and DOM map labels. Its safeRect uses existing HUD_INSET top=72/bottom=88 and all available board width. **src/runtime/createWebGpuHost.ts** already observes board size via ResizeObserver and recalculates rendering/picking against the measured canvas.
- **src/components/hud/panels/BuildPanel.svelte** uses command-plates and a text-button item list. BUILD_GROUPS and BUILDING_CATALOG already provide item ID/action, building footprint and nominal cost. **src/assets/sunny-diorama/build-categories/** and **build-items/** contain the new 4 category images and item thumbnails.
- **src/components/hud/panels/LinesPanel.svelte** owns route list/service controls and embeds **RouteEditor.svelte** during a draft. RouteEditorView already has waypoint selection, interaction mode, undo/redo, connection status, warnings, initialFleetCost and canSave. ShellRouteListItem.service already has assignedFleet, targetHeadwaySeconds and dailyOperatingCost.
- **InspectPanel.svelte** already renders stop/platform, building and vehicle details, but ShellInspectorState deliberately has no screen coordinates. The GPU host's click handler owns actual hit-testing. The selected tile is already in `ui.selectedId` (including navigation-opened inspection); it can be projected through the shared transform without capturing pointer events.

## 1. One right-hand dock, with a genuinely narrower map

- Reorganize the active-city shell as a **game-stage** (map and local HUD) with an optional right **workspace-dock** sibling. Keep Topbar spanning the full top band so the three clusters remain legible at 1024px. The dock occupies its own column from `top: calc(var(--hud-top) + 12px)` to `bottom: 12px`; the bottom shelf and zoom controls live only in the map column, so the dock does **not** reserve the bottom HUD inset.
- When a destination is open, use CSS grid columns `minmax(0, 1fr)` and roughly **360–400px** for the dock, clamped so the map remains usable at the 1024px minimum. Without a destination, render one full-width map column.
- Position CommandPanel in the dock rather than over the map. Keep its header, Close action, and vertically scrollable body. Remove **`pinned`**, `.command-panel--pinned`, and `.command-panel-overlay` (and their obsolete tests); also delete the 1143px `.overlay-legend` workaround for the old centred Data panel.
- Replace viewport-relative widths/heights on `.command-panel__body`, `.action-feedback`, and `.command-shelf` with dimensions relative to their actual stage/dock container. Set `container-type: inline-size` on game-stage and use an **@container** rule to compact the shelf when the stage is narrow. No separate dock-open compact-state flag.
- Keep GameCanvas/board and MapTextOverlay in the **same** narrower game-stage. The existing ResizeObserver, `boardTransform` and GPU picking then use the measured width. Null/Fit camera refits automatically; zoomed state follows existing clamping. **No right-side HUD_INSET, second camera, saved camera change, manual remount, or new runtime setting.**
- Topbar remains above the dock, while ActionFeedback, CommandShelf and zoom buttons stay visible and do not intercept bare-map clicks. Preserve destination gates, keyboard shortcuts, Escape/Close focus, route-draft pinning, and bottom-row tile interactions.

## 2. Inspect: selected-tile popover, not a dock

- Render InspectPanel only when `snapshot.shell.inspector` exists and no command destination is open, as today. **Anchor to the selected map tile, not a DOM click.** `ui.selectedId` already records `"x,y"` for stop, building and vehicle inspection; for vehicles it is the original clicked tile, not the moving vehicle position. `focusWaitLocation` sets it when navigating to a stop.
- Reuse exported `parseSelectedPoint(snapshot.ui.selectedId)` from `src/runtime/runtimeSelectors.ts` and `getBoardTransform({width,height},snapshot.state.map,snapshot.camera)` to project the selected tile center, matching MapTextOverlay. Measure stage/card dimensions with Svelte's `bind:clientWidth`/`bind:clientHeight`, with no custom observer.
- Use one small pure `placeInspectorPopover` helper. If the projected selected-tile anchor is **outside the visible stage map area** (stage horizontal edges with padding, and top/bottom HUD safe bands), return `null` and hide the popover rather than pinning it to an unrelated screen edge. If the anchor is visible, position right/below or flip left/above and nudge the card inside the safe bands. Unit-test ordinary placement, edge flip, off-screen hiding after pan/zoom, camera reprojection and zero-size measurements.
- The popover follows the **tile's** position when zooming, panning or fitting but **never tracks a moving vehicle** between ticks. If camera movement carries the selected tile out of the visible stage map area, hide the popover until its tile becomes visible again. Re-selection or programmatic wait-location focus repositions it automatically. Existing Escape and panel actions remain unchanged.
- **No click handler in GameCanvas, App anchor state, navigation fallback state, Rust, wire or save changes.** Preserve current test IDs and accessible actions.

## 3. Build: use the shipped assets and readable item cards

- **Keep `CommandPlateGrid.svelte`** and its 2×2 grid plus arrow-key navigation. Swap the four imports from `command-plates/` to `sunny-diorama/build-categories/`, then delete the now-unused old images. Verify `object-fit: cover !important` with the new art at narrow widths.
- `BUILD_GROUPS` remains the **only** Build item catalogue. Extend `BuildMenuItem` in `src/domain/catalog/buildGroups.ts` with `description` and display-only `cost: {amount, unit: "each" | "perTile"} | "free"`. Building items derive cost from `BUILDING_CATALOG` (including stops/stations); the other nominal hints mirror the current Rust rules: road **$100/tile**, dual road **up to $200 per stroke tile when both lanes are newly built**, track **$500/tile**, compact/standard roundabouts **$1,000/$2,000 each**, zones **Free**. These are *nominal* hints, not authoritative totals for replacing/partial strokes; existing cursor previews and Creative cost policy stay authoritative. Pin the non-building values against known core constants in a focused test.
- Each item card simply renders its catalogue description, name, nominal price/unit, thumbnail and known footprint/placement cue. Resolve the 26 existing `build-items/*.webp` files by item ID with one eager `import.meta.glob` and a focused test that every item has art; avoid 26 manual imports or a new asset framework.
- Add pure `buildGroupShortcuts(group: BuildMenuGroup)` in **`src/ui/shortcuts.ts`**, importing only the catalogue type, to map the first nine visible items in order to 1–9; both the badges and `App.svelte`'s **existing** window key handler read it. Keep `src/domain/catalog/buildGroups.ts` keyboard-agnostic. **While a Build leaf group is open, its number keys win over the global road presets**. At the top-level category grid or with Build closed, the existing 1/2/3 preset behavior remains; `0` remains Fit. Never intercept text inputs, modifiers or active route drafts. Assert Roads-group 1/2/3 map to `ROAD_PRESET_KEYS`.
- Place Rotate and a concise active-item description in the Build footer using existing selection, rotated footprint and group hints. Preserve keyboard focus through category drilldown: focus Back (or the first item) after opening a leaf group, then restore focus to that category plate when Back returns to the grid. **Escape still closes the Build workspace and returns focus to its CommandShelf trigger** (current `createGameRuntime.ts:handleEscape` behavior); do not repurpose it as Back. Use only a small component-local previous-group reference if needed, not another runtime state. No new gameplay fields or Svelte cost calculations.

## 4. Lines and route drafting

- Keep line creation, fleet management, selection, rename, colour, wait-location jump and delete actions. Restyle the existing cards within the dock without removing controls.
- Redraw RouteEditor as a **vertical rail** of numbered waypoints. An edit already has `selectedRouteId`; use the selected `ShellRouteListItem.color`. New unsaved lines use the theme accent. Keep per-waypoint move/remove, Append/Replace/Insert after, Reverse, Undo/Redo, connection status, loop/shuttle, warnings and Reload; group actions in a compact toolbar.
- Retain the existing Save logic and labels: **Save & run · $X** only when `initialFleetCost` exists, otherwise **Save & run**, and **Save route** for edits. Never recompute fleet price in Svelte.
- **No App-side recently-saved ID.** `createGameRuntime.ts:saveRouteDraft` already computes a new route ID for optional deployment from a pre-save ID set. Reuse that diff for *all accepted creates*, including without initial deployment, and set `selectedRouteId` in the accepted **current** create branch before committing. Do not select on rejection or superseded saves. Keep existing deployment/error handling. Edits retain selection.
- The selected line's **existing service card** is the after-save summary; highlight it and scroll it into view **once** on selection change. It already renders assigned fleet, target headway and daily operating cost and updates if deployment completes. Omit null values, no new summary component or wire field.

## 5. Data, City, accessibility and boundaries

- Place DataPanel and CityPanel inside the same dock and use the existing cream card/button/input styling; preserve their existing content, save/busy gates, links to overlays and city-list actions.
- Preserve keyboard reachability, visible focus rings, semantic headings, Escape, disabled actions, topbar and shelf controls, the existing screen-reader feedback region and toast visibility. A dock is a **non-modal region**: do not trap focus or put an invisible pointer-blocking backdrop over the board.
- **Out of scope:** City Library/New City and WebGPU textured building/trees (HPA-677), new art generation (HPA-676 already delivered), new gameplay rules, Rust, Tauri/WASM wire contracts, persistence, screenshot-golden testing, mobile redesign, generic layout/overlay frameworks.
