## Outcome and constraints

Finish the Sunny Diorama right-dock experience while preserving the existing playable transit operations loop. A player can compose and edit a route, understand the first fleet purchase *before* committing, manage saved services through compact controls, inspect map objects (including vacant zoned land), and switch Build/Lines/Data/City without the map unexpectedly sliding or zooming.

- Keep Svelte 5 as presentation, TypeScript runtime as UI orchestration, and Rust caelum-core as the authority for route validation, initial-fleet sizing, purchase, operations and growth. Allow **one narrow Rust preview DTO extension** to supply the requested fleet/target/cost summary. Do not add a new backend method, persistence schema, renderer pipeline or general service calculator.
- Use the existing runtime snapshot, route-draft generation/selection methods, service metrics, overlay catalog and city rename action. Add only small view projections/actions needed for new controls. No extra modal/dialog framework, generic store, derived pricing formula, art, or dependency.
- A route draft continues to gate workspace switching; keyboard focus, Save/Cancel/Reload semantics, wait-location navigation, existing error announcements and two-click Delete protections remain intact.
- CityList **visual restyling**, New City, City Library, top bar, markers and map art are HPA-978/HPA-979 work. A tiny CityList active-row *read-only* option is allowed solely to prevent duplicate active-city rename controls in this dock.

## 1. Route editor

Use the established dock and existing RouteEditorView rather than another draft model.

- **Keep the existing native Loop/Shuttle radio group** and style its labels/checked states as a segmented control (hide the radio dots visually, not from accessibility). This matches the mockup while preserving keyboard-arrow radio navigation and existing `getByRole('radio')` E2E/unit contracts. Do not replace the radios with separate `aria-pressed` buttons just for styling.
- Render each numbered waypoint on the existing vertical rail. Row click calls onSelectWaypoint(index, interaction) and visually highlights it. Each row owns accessible move-up, move-down and remove buttons. The button first selects its row, then calls the existing move/remove handler; those runtime methods are synchronous, and selection-only changes do not restart the preview. Disable bounds actions and keep missing-stop guidance. Remove the shared Move/Remove toolbar controls.
- One compact, wrapping toolbar contains Append, Replace, Insert after, Reverse, Undo and Redo. Replace/Insert still require a selected row, and clicking the map after choosing Insert after inserts after that row. Preserve all preview warnings, rejected-draft state, route repair guidance, reload-edit-conflict, Cancel and history.
- For **new drafts only**, render an **After saving** summary with the Rust-quoted *expected* first fleet count, target headway and estimated daily operating cost. For a known Standard shortfall, match the low-money mockup: **Fleet: None yet**, target from the quote, **Running cost: $0/day**; explain that the player can deploy later. For an affordable Standard or Creative create, show the projected count, target and nominal estimated cost. In all cases the actual fleet/cost after Save comes from the selected Lines card; quotes may change before purchase. Do **not** put an After saving section on edits, because pre-edit values are not a post-edit forecast. Do not recompute fleet or operating cost from travel seconds in TypeScript.
- Keep one large primary button. A new, valid route with a nominal quote displays Save & run plus the formatted quote when the first fleet is affordable; otherwise the Standard-mode editor shows an inline warning (needs X, available Y) and the visible label **Save without fleet**. Edit remains Save route; unavailable quotes keep the existing Save & run fallback, not a new disabled gate.
- One pure **initialFleetShortfall(state, quoteCost)** predicate (Standard only, budget < cost) drives both the displayed warning and a Save-click-local boolean for suppressing the *expected* insufficientBudget toast. Creative still shows nominal prices but never warns from budget. The backend **still attempts deployment** when a valid quote exists and Rust reauthorizes at execution. **Do not call `dispatchNow` and then restore `rejection`**: it publishes the transient `role="alert"` before returning. In the existing serialized `deployCreatedLine` path, call `backend.dispatch({type:"deployInitialFleet", lineId})` directly, apply normal `dispatchNow` rejection semantics *before* publication, and invoke `commitDispatchResult` **once** for the deployment result, passing the same intent. If a known shortfall yields `insufficientBudget`, preserve the appropriate previous feedback without an intermediate alert; if the budget changed only after click, set existing `savedWithoutFleet` context before the single publish. Preserve normal successful-deployment rejection clearing, dirty state, backend error handling, token/supersession safety and the existing no-fleet recovery UI.

**Minimal quote seam:** In `crates/caelum-core/src/preview.rs`, replace the existing nullable `initial_fleet_cost` output with a single nullable `initial_fleet` value containing `vehicles`, `target_headway_seconds`, `cost`, and `estimated_daily_operating_cost`. `new_draft_initial_fleet_cost` already calls `initial_fleet(... DEFAULT_TARGET_HEADWAY_SECONDS)` and discards the count; reuse that count and `operating_cost::fleet_daily_operating_cost(request.mode, vehicles)` (the direct shared Rust operating-cost helper, avoiding unnecessary Option wrapping). Reuse the existing preview response across WASM/Tauri, update `src/runtime/backend/types.ts` and its single normalizer in `backend/shared.ts`, and project it to `RouteEditorView`. **Breaking wire replacement is fine** for this pre-release project; update fixtures/tests in this PR. No new Rust gameplay intent, extra preview request, persistence format, or TS pricing calculator.

## 2. Lines cards

Restyle the current list rather than replacing it. Show a colored chip labeled with **route.name**, a pencil that toggles an inline name input, status pill, estimated running interval (e.g. Every 6.5 min), one target-headway input, assigned fleet, Daily cost and no-fleet reason/recommendation/deploy affordance.

- A compact **fixed-layout − / fleet count / + stepper** invokes **onRetireServiceVehicle** and **onAddServiceVehicle** only when their respective existing Rust-derived canRetireVehicle / nextVehicleCost gates allow them. Keep both buttons **rendered but disabled** whenever the corresponding action is unavailable or pending so the stepper does not move horizontally as Rust offer/can-retire state changes. Keep pendingServiceActions to prevent duplicate commands. Preserve `route-add-vehicle-*`/`route-retire-vehicle-*` test IDs, show next-vehicle nominal cost and no-refund retirement in accessible labels/hints, and update old `toBeNull()` tests to check disabled buttons.
- Use one small **InlineNameEditor.svelte** shared by the route-name pencil and City header pencil, with value/label/disabled/onCommit, focus on activation, trimmed nonempty input, single commit on Enter/blur and Escape restoring without propagating to the dock. Replace the Lines card's persistent input rather than adding another editor; do not alter the legacy CityList editor (HPA-978 owns its restyling). Keep `data-testid="route-name-${id}"` on the **visible display** and the **edit input**, but update input-only tests to click a new accessible rename pencil first; do not rename by selecting a line.
- Keep headway validation, no-fleet manual Deploy, wait-location diagnostics, route color palette, two-step deletion, Edit/Pause/Resume controls, and test IDs. Icons can be lightweight inline symbols/SVGs with explicit aria-labels; do not add an icon package.
- Continue the existing once-per-selection scroll into view, including immediately after Save & run; do not add a duplicate saved-route summary cache.

## 3. Inspect and vacant zoned land

Keep the popover *stage-local*, tied to ui.selectedId and placeInspectorPopover; do not add DOM click-coordinate state or move it into the dock.

- Replace numbered section headings with the selected stop, station, building or vehicle title; retain route chips, platform reassignment, live load/destination and workplace status. Provide a Close button calling one minimal `clearSelection` RuntimeController action that clears selected tile/vehicle/node kind only. Use this same action as the **last** Escape branch in `createGameRuntime.ts::handleEscape`, after drag, draft, dock and active tool checks. Do not clear a selected line or gameplay state.
- On stop/station, aggregate displayed platform occupancy and capacity to an accessible queue bar plus numeric text, while preserving per-platform occupancy and serving-route wait information.
- Add a small pointer/arrow using CSS, oriented toward the selected tile based on the existing placement result. If required, extend the small placement helper's return data with a horizontal/vertical placement side; avoid a second positioning system. Keep its existing off-screen hide, edge-flip, safe-area and zero-size behavior.
- Select already records a vacant tile ID. In `runtimeSelectors.buildInspector`, after existing vehicle/node/building branches, return a **zone** inspector for `kind === "empty"` with a non-null `area`. Project **near a running stop/station** with existing `stopCoverageRadius` (bus stop 2, terminal 4) and `METRO_STATION_COVERAGE_RADIUS` (4): check Chebyshev tile distance and present node with a line whose existing `routeServiceStatus(...).primary === "running"`. Say **"near a running stop"**, not "guaranteed to grow"—Rust's active-services rules and footprint placement remain authoritative, and broken/missing-waypoint services may not support growth. No new Rust coverage algorithm.
- Unzoned empty tiles continue to have no inspector. Selected map and route interactions keep their existing precedence.

## 4. Data and City

- Use OVERLAY_CATALOG descriptions as concise inline helper text on the Coverage/Crowding/Demand/Traffic tiles. Existing legend remains on the map. Preserve toggle-to-clear and active state.
- Style the existing metric links as cards with Late → Traffic, Unserved → Coverage, Avg Wait → Crowding. Keep their true metric values and accessibility, no misleading new calculations or duplicate overlay legend. Drop the 04/05 section labels.
- City header uses `activeCity.name`, the shared pencil editor, save status and Save action; keep overview, retry/dirty/busy gates and city list. The approved `t2-city-panel.png` shows the active city as a **read-only Playing row** in Your cities while the header alone owns rename. Add a narrowly scoped optional CityList prop used only from CityPanel to make the **active-row name read-only**, but **retain its existing two-click Delete button** (a small trash icon is acceptable despite the mockup). This is the **only** accessible in-game path to delete the active or last city; without it the native Tauri shell cannot return to the Library/New City flow and existing `appShell.test.ts` deletion regressions fail. Preserve City Library behavior, inactive-city Load/Delete, delete busy gates and shared row styling (HPA-978 owns styling). Remove numbered labels.

## 5. Preserve exact map transform during passive dock resize

**Decision:** Keep the HPA-977 *no-jump at any zoom* requirement, including the default Fit view. The review correctly identified that simply rebasing `zoom` and `center` then calling `clampCamera` cannot meet it: Fit letterboxing triggers automatic re-centering. We **do not** weaken the ticket or globally loosen user-driven camera clamping.

- On a **passive, already-mounted** canvas size change, preserve the old `getBoardTransform` **absolute scale and offsetX/offsetY**, not a last-pointer anchor. The dock only changes the right-side stage width; its top-left coordinate remains fixed. Keeping this transform therefore keeps *all* still-visible map tiles in the same screen positions, including a tile under the cursor. A right strip of the map can be clipped or letterboxed after dock transitions; pressing **Fit** intentionally brings the whole map into the currently available stage.
- Add one small `rebaseCameraForResize(oldBoard,newBoard,map,camera)` helper in `boardTransform.ts`. Derive `zoom = oldTransform.scale / fitScale(newBoard,map)` and center from the new safe-viewport midpoint and old offsets. Mark the result as a **passive retained view** (one small optional Camera flag/variant), and make **`resolvedCamera` return a retained view without calling `clampCamera`**; this is essential for render, picking, overlays, wheel anchoring and pan to read the *actually drawn* pixels. `null` still means explicit Fit. Passive retention allows sub-Fit relative zoom after stage expansion and letterboxed margins after Fit; coalesce back to `null` only when the **complete** projected transform matches canonical Fit within tolerance, not just `zoom≈1`. The retained flag is local-only, never persisted.
- Existing clamp and max-zoom rules still apply to deliberate user navigation, **but must not silently change scale on the first input**. For a retained view with `zoom <= 1` (the full map fits), **pan is a no-op**, as for ordinary Fit. Zoom Out is a no-op; a small Zoom In uses `maxZoom` and a lower bound of **`min(1, current.zoom)`**, staying retained while still below 1 instead of snapping larger to 1. `zoomCameraAt` must calculate its anchor from the *unclamped retained camera*; keep the result retained until crossing into normal clamped navigation. Explicit Fit resets to `null`. Do not add a new global camera store or duplicate transform.
- Rebase **once** on a genuine positive-size change in both the shared host's `ResizeObserver` callback and `handleResize` fallback, against the previous rendered `boardCssWidth`/`boardCssHeight`. **Update both boardCss dimensions synchronously when rebasing, before `ctx.onCameraChange` or rendering**—rAF-only updates in `syncSize` allow consecutive observer batches to rebase twice against stale dimensions. Skip first mount and equal size. In `detach()`, reset **both** boardCss dimensions to zero alongside observed sizes, so a newly loaded city mounts with its fresh Fit camera rather than inheriting an old city's size. Keep drawn-frame picking, hover, labels and both WebGPU/Canvas2D aligned; no App/renderer-specific duplicates.

**Invariant:** For any screen point that stays inside the stage and visible map, dock open/close/switch preserves CSS pixels per tile and the world tile at that screen point at both Fit and zoomed views. Explicit Fit **may** change scale/position to reveal the whole map, by design. A clipped point hidden behind the dock cannot be clicked while hidden, but its position does not shift.

## Out of scope and risk controls

- No new marker art, sprite pipeline, New City/Library/topbar polish, autosave or Crossroads changes.
- No new backend API, Rust service **calculation**, save schema/version, UI global store, modal system or generalized camera framework. The existing Rust preview response gains only already-derivable summary fields.
- Preserve data-driven headway/fleet/status/queue content; a visual mockup must not cause invented service figures.
- New UI affordances must have accessible names and keyboard behavior; do not silently weaken route draft and busy/pending guards.
- Camera behavior is more important than a cosmetic pixel match: prevent regressions in pointer hit-testing after layout resize and in both existing render paths.
