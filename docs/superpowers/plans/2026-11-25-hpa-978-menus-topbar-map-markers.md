## Approach

Use the actual Linear HTML references and supplied before/target screenshots (no need to recreate all before captures). Implement CP1–5 in order, one independently CI-green implementation commit per checkpoint on this same PR; run affected checks at each checkpoint, then full CI gates at completion. CP5 is an atomic, separately bisectable shared renderer contract change. Use repeatable real-browser Playwright tests for behavioral/pixel acceptance; finish with a focused browser/Playwright MCP visual E2E session that also traverses the real save lifecycle, without replaying every test. No new images, packages, pipeline or simulation rules. Reuse HPA-977 city rename semantics, HPA-1144 shared frame/Canvas2D path, and HPA-979 shipped art. Do not change unrelated dock controls or native UI.

## Risk and mitigation

- CP5 is the primary risk: a wrong sprite stride, firstInstance or byte offset, premultiplied tint, or Canvas2D full-image drawing of half-rail crops can break the second range and WebGPU/Canvas2D capture parity; sharing one projection-cache slot between the two ranges would also cause per-frame re-projection of the whole scene. Keep CP5 atomic, extend existing captureFrame renderer tests for both modes (including source crop, ordered split and empty ranges), assert independent host projection-cache identity reuse, and run the same focused pixel scenario through the production WebGPU and forced-Canvas2D startup paths. Keep deterministic draw-count assertions; no main-vs-branch timing comparison without evidence of a regression.
- CP1 changes outer city metadata: use matching v9 namespaces, verify immutable template metadata through the existing adapter contract tests and browser save/reopen E2E. No migration or destructive cleanup. No snapshot schema change.
