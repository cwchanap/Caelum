## Task 1 — Fix passive dock resize without moving the map (highest risk)

**Decision:** The original HPA-977 acceptance requires no map jump even at default Fit. The review's suggested simple rebase + normal `clampCamera` fails this requirement on letterboxed Fit; it is *not* enough to loosen the test. Make **passive layout** preserve the same rendered CSS scale and offsets, while intentional Fit continues to recenter into the available viewport.

1. Start **red/green with fast pure `boardTransform` Vitest tests and the existing `FakeResizeObserver` host test**, then implement and re-run them. Wire and execute the existing `tests/e2e/commandShelf.spec.ts` geometry test **after** the shared host implementation (CI/MCP) instead of front-loading slow failing Chromium runs. Do not write a giant matrix up front.
2. In `boardTransform.ts`, implement pure `rebaseCameraForResize(oldBoard,newBoard,map,camera)` using old absolute `getBoardTransform` scale and **offsetX/offsetY**. Derive zoom relative to new `fitScale` and center from new safe midpoint. **No pointer anchor/state.** A tiny `retained` Camera flag marks the passive result, and **`resolvedCamera` must bypass `clampCamera`** for retained views so all rendering, picking, overlays and zoom anchoring use actual pixels. This is necessary for letterboxed Fit and possible zoom below 1 after expansion. Keep user-requested navigation constraints, and coalesce to `null` only if the entire transform matches canonical Fit.
3. On retained views with `zoom <= 1` (full map fits), make **pan and Zoom Out no-ops**. Tiny Zoom In steps start from the actually rendered scale/offset (not clamped Fit), using a floor of `Math.min(1, current.zoom)` and staying retained while below 1. Check wheel anchor math against the drawn point; do not silently snap larger on a pan/Zoom Out. Explicit Fit resets to `null` and intentionally recenters into the current stage. User-driven clamping remains unchanged outside retained handling.
4. In shared `createGameHost.ts`, apply rebase on each **genuine** positive size change in both ResizeObserver and window-resize fallback. Compare against previous rendered `boardCssWidth/boardCssHeight`, then update **both boardCss dimensions synchronously in the resize handler before publishing the rebased camera** (otherwise two observer batches before rAF double-rebase against stale dimensions). Skip first mount/equal sizes; reset both boardCss dimensions to **zero in `detach()`** alongside observed sizes, so a newly mounted city cannot rebase its fresh Fit camera against an old city. Render and hit-test with the same transform; no App renderer-specific/Canvas2D fork.
5. **Replace**, do not duplicate, `commandShelf.spec.ts:71`'s HPA-696 `expectMapFitsCanvas("dock open")` assertion with map-stability checks using existing `runtimeSnapshot`, `mapTileViewportPoint`, `mapWorldViewportPoint` and `hoverMapTile` helpers. Retain explicit Fit and rightmost-clickability tests but invoke Fit before asking that the whole map fits the docked stage.

**Focused acceptance:** Pure camera tests for (a) zoomed open/close retaining scale+offset; (b) default Fit → dock open → close preserving still-visible map points and coalescing to `null` when equivalent to canonical Fit; (c) docked Fit → close preserving its smaller scale/margins; (d) **retained sub-Fit pan/Zoom Out no-ops and tiny Zoom In/wheel anchors without a jump**. Add focused existing `FakeResizeObserver` host tests for **no first-mount/equal-size rebase, two resize batches before rAF (no double rebase), and detach→new-city remount**; cover window fallback in existing host test. After host wiring, **commit and execute Playwright via MCP**: unchanged tile under in-stage cursor at Fit/zoomed for dock open/close/switch/route-path click → Lines, correct picking and explicit Fit. Run at 1440×900; narrower screenshot where helpful. No human acceptance step.

## Risks / decisions not to expand

- New initial-fleet preview estimates **do** include Rust-derived fleet size, default target and nominal daily cost. Display them as projections, not guarantees; after Save the selected card shows actual values. Do not add a second API or TS service formula.
- In Creative, nominal prices are informational; Standard-mode budget warning does not block create or bypass Rust authorization.
- The passive retained camera can carry below-Fit relative zoom or letterboxed offsets solely to prevent dock-induced movement; `resolvedCamera` must not clamp it. At sub-Fit, pan and Zoom Out are no-ops; incremental Zoom In remains anchored to what is drawn. Synchronous resize dimensions avoid double-rebase, and detach resets size. Ordinary navigation clamps deliberately; Fit intentionally re-centers.
- Vacant zone reach uses existing TS coverage radii and running-line status, worded as proximity only; do not duplicate Rust's growth/active-service calculations.
- Art creation is a *different* ticket (HPA-979), and menu/marker styling is HPA-978; do not fold either into this PR.
