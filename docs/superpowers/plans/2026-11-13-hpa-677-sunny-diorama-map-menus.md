## Task 3 — Typed asset table, mipmapped array upload, and scene instance data

1. Create a single focused `src/render/webgpu/spriteAtlas.ts`: explicitly map `Exclude<BuildingType, "busStop" | "metroStation">` to twelve imported WebPs and include the three tree variants in a stable 15-layer order. The building types remain checked by TypeScript; no `import.meta.glob` for the map sprites, new art or asset framework.
2. In the existing async production `createWebGpuHost` factory, decode all fifteen shipped assets using `new Image()` / `await image.decode()` on Vite URLs, not `fetch(url)` → data: URI (Tauri's CSP restricts fetch under `default-src 'self'`). Validate building dimensions against `BUILDING_CATALOG` native width/height × 192 and trees against 192×192; fail clearly on bad loads. Allocate **one** `rgba8unorm` `texture_2d_array` with `size: [576, 384, 15]`, `mipLevelCount: 5`, and numeric `usage: 0x04 | 0x02 | 0x10` (`TEXTURE_BINDING | COPY_DST | RENDER_ATTACHMENT`) rather than the ambient-only `GPUTextureUsage` globals (matching renderer.ts). Reuse one **fixed-size 576×384 2D canvas** for all mips: set high smoothing, `clearRect(0, 0, 576, 384)` before every scaled draw, and **never resize it**, as resizing resets image smoothing. Upload only the top-left `(sourceWidth >> level, sourceHeight >> level)` crop via `queue.copyExternalImageToTexture(source, { texture, mipLevel: level, origin: { z: layer }, colorSpace: "srgb", premultipliedAlpha: true }, { width: w, height: h })`. The rest of each layer remains transparent; the sprite sampler is linear/trilinear. No shelf packer, gutters, atlas rectangle table, size-limit branch or GPU mip shader.
3. In `mapBatch.ts`, keep deterministic hashing and filtering in place and return `{ vertices, sprites }` from `buildMapBatch`; use **one scene cache** for both arrays. Emit tree instances where the canopy was created, using `Math.floor(tileHash(x, y, 5) * 3)` (hash is fractional), preserving the original 12–18 world-pixel canopy and all exclusions. **In the same Task 3 change**, update `createWebGpuHost.ts:sceneVertices`, all affected assertions in `tests/render/webgpuMapBatch.test.ts` (~15 calls), and `tests/render/webgpuRenderer.test.ts:gameplayFrame` to read `.vertices` so type/unit tests stay green before Task 4.
4. Emit **one sprite instance per building** with the **rotated footprint center**, *unrotated* native width/height × tileSize/2 as world half-extents, and angle from `building.rotation`. Per instance: world origin, angle, half-extents, `uvScale=(sourceW/576, sourceH/384)`, and layer; clip-scale slots are filled by host projection. Do not swap half-extents and rotate a second time. The stable sprite row order is trees then buildings.
5. **Do not remove the procedural roofs or tree canopies yet.** Task 3 prepares the data and texture upload without changing visible output; Task 4 replaces geometry only once the textured pass is working. Unit tests cover typed mapping, image validation/mip dimensions, deterministic all-three-tree variants and exclusions, and 0/90/180/270 instance footprints.

**Proof:** The 15 existing assets are loaded into one layered texture; `buildMapBatch` returns one building instance per placed building; no visual blank period between commits.

## Risks and bounded mitigations

- **Fit-scale aliasing / image edges:** Five individually downsampled mip levels in separate texture-array layers; non-sRGB color handling and an explicit premultiplied-alpha sprite blend. Pin behavior with the existing real-WebGPU pixel-readback helper.
- **Rotation and shadows:** Native width/height plus one world-space rotation; one footprint shadow only for sprite-bearing buildings, **none for procedural bus/metro markers**, with focused pixel/sample bounds and pure geometry tests.
- **Asset startup:** Load and upload only the 15 shipped images once before first frame. Match jsdom's real-host teardown test with a narrow mock of the loader, extending the existing GPU fake instead of introducing a production loader interface. Keep fatal errors rather than an asset fallback.
- **Sharing CityList:** Reuse the one component and style only the library's parent scope; stable city.id color prevents rename flicker.
- **Scope/CI cost:** One PR, existing GitHub Actions jobs, one new pixel oracle and narrowed screenshot views; no new art, persistence, native IPC or new testing framework.
