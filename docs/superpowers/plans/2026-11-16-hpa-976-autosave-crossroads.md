## Step 1 — Tests first: eligible autosave with the current busy gate

1. In `tests/runtime/citySaveRuntime.test.ts`, reuse the existing real `createGameRuntime` fixture and `tests/runtime/delayedCitySaveStore.ts`. With fake time, cover eligible dirty 60s save (same `updateCity` store), idle/clean/no-city skip, busy skip, route-draft and road-gesture skip, no duplicate timer after `start()`, and interval teardown on stop/dispose/fatal. Assert **stop → restart** reinstalls exactly one interval.
2. Implement one nullable `autosaveTimer` in `createGameRuntime.ts`. Install `setInterval(60_000)` in `start()` (guarded against duplication); clear and null it in the **existing `stopRuntime()`**. Because `stop()`, `failBackend()` and `dispose()` all use `stopRuntime()`, avoid duplicate cleanup in each caller. At interval tick, require live active city, dirty, `!workingSave.isBusy()`, `ui.routeDraft === null`, `ui.drag === null`, `activeRoadMutation === null`. Otherwise **skip**; next minute retries. Call the existing `workingSave.controller.save()` directly. No autosave queue, special controller method, or save pause.
3. In `tests/runtime/workingSaveRuntime.test.ts` first assert one `save: "idle" | "saving" | "failed"` read-only view discriminant. Admitted Save/Retry/autosave transitions to `saving`; success → idle and clean; failed update → failed and still dirty; busy rejected Save does not change status. Include `awaitGameplayIdle()` throwing and backend snapshot/storage exceptions to prove the final status is published without an intermediate `busy=false, save="saving"` snapshot.
4. **Implement save/error isolation inside `runExclusive`.** Pass a narrow `channel: "error" | "save"` from the caller: on `"error"` retain generic `error` begin/end semantics, but on `"save"` never clear/overwrite `error`. Set `save="saving"` after admission; update `save` on **both** normal and thrown completion inside `runExclusive`, before its single `finally` publication. This covers throws in `awaitGameplayIdle()`, not just the save callback. Reset a prior failure only after a successful save or city replacement; the next eligible attempt may show saving while retrying. Keep the one existing busy gate and store update.
5. The gate currently **drops** ticks and clicks instead of deferring them. The draft/gesture guards avoid costly interruptions but do not eliminate isolated click collision during a brief save. Test one realistic interaction boundary; fix further only on a reproducible case, not with an input queue or new persistence framework.

**Proof:** Focused runtime red→green tests for successful/failing/throwing autosave, independent generic errors, no skipped route/drag commit due to *starting* an autosave, and stop/restart lifecycle.

## Step 2 — One shared status, browser unload and safe Tauri close

1. Create one pure `src/runtime/saveStatus.ts` formatter `saveStatus(view, nowMs) -> {label, canRetry}`, ordered **Saving… > Couldn't save > Saved N s/min ago**. Return label **"Couldn't save"** without appending "Retry"—the Topbar's real button supplies that word. Dirty running ticks do not mask the last-successful save age. Add focused node unit tests for elapsed age, failure, saving, and dirty-after-success.
2. In `App.svelte` use one ~1s clock/timestamp and derive status once, passing it to both `Topbar.svelte` and `CityPanel.svelte`. **Only Topbar renders a Retry button:** keep the existing `<span class="chip topbar-save-status" data-testid="topbar-save-status">` with status text and an inner focusable `<button type="button">Retry</button>` when failed, disabled while busy; add only the minimum chip-button styles. CityPanel renders the **same status text only** and keeps its existing `Save Now` button and `data-dirty={dirty}`. Avoid two onscreen Retry buttons, a new status component or duplicate date logic.
3. In `App.handleSaveCity`, **do not call `beginPersistenceMutation()`**. It would clear `cityListError` even when Save fails; call `runtime.persistence.save()` directly and `refreshCities()` only on success. Keep `beginPersistenceMutation` for create/load/rename/delete. Test: failed Save/Retry while a city-list error is present leaves the list error and "Retry city list" intact, and a successful Save refreshes the list.
4. Browser: register a synchronous, dirty-only `beforeunload` listener on mount, querying the **current** runtime snapshot and calling `preventDefault` / legacy `returnValue`. Remove it on teardown; no async IndexedDB writes. Verify with a browser dialog after user activation.
5. Tauri: add mandatory `core:window:allow-destroy` in `src-tauri/capabilities/default.json`. Register native `getCurrentWindow().onCloseRequested` only for the Tauri host; because registration returns `Promise<UnlistenFn>`, use a local `unmounted` flag to immediately unlisten if registration resolves **after unmount**, or store the unlisten callback for synchronous cleanup. On dirty close, await existing `runtime.persistence.save()` unless busy. First failure/busy prevents closure; a **second explicit close** may exit unsaved. Record the active city ID and `savedAt` at the blocked close: if either changes due to a successful background/manual save or city switch, **invalidate** the escape privilege, even if the city was dirtied again before the next close. Reset when clean. No new native command/dialog or native store failure injection.
6. **Keep tests green in this Step 2, not Step 5.** Update `tests/ui/appShell.test.ts`, `tests/ui/cityPanel.test.ts`, and the existing **`tests/e2e/topbarViewport.spec.ts` exact assertions** that currently expect `"Saved"` / `"Unsaved changes"` (including its dirty fixture and viewport loop). Assert both status areas match, Save Now and single Topbar Retry behavior, dirty-only beforeunload, native registration/unmount race, first-block/second-close and stale escape invalidation. Keep existing viewport geometry checks at 1024×768 / 1440×900.
7. For native behavior, real `bun run tauri:dev` MCP smoke later covers close/reopen and macOS Cmd+Q; mocked Svelte UI tests cover failure/busy/escape branches without changing the Rust store.

**Proof:** Last-save status remains truthful during running ticks, one keyboard-focusable Retry exists, city-list error survives failed Save, no Tauri listener leak or stale second-close permission, and the preexisting viewport E2E checks pass after the UI change.

1. 3. In `network.rs::resolve_route_legs`, resolve normally. Only if a bus **service** leg returns `NetworkDisconnected`, clone the map once for that route-resolution call:

## Risks and implementation guardrails

- **Two separate error surfaces:** `runExclusive(channel="save")` must set `save` in its own `try/catch/finally` before publishing, including `awaitGameplayIdle` failures, without clearing generic `error`. `App.handleSaveCity` must preserve `cityListError` on failed Save/Retry and only refresh cities on success.
- **Tauri close registration:** The listener is asynchronous to install; guard teardown with `unmounted`, and **invalidate** the second-close escape when the city or its `savedAt` has changed. A failed/busy close may permit a deliberate second exit only if it refers to the same still-unsaved state.
- **Roundabout diagnosis:** Once cloned ordinary road arrows are cleared, captured roundabout port directions must be cleared in the clone too; `port_matches_current_map` otherwise drops previously connected ports.
- **Timer lifecycle:** `stopRuntime()`, not ad hoc duplicated dispose/fatal cleanup, owns interval cancellation; repeat start must not double timers.
- **No hidden E2E failures:** Change exact saved/dirty viewport assertions during the **Step 2 UI change**. A DOM-injected trip-warning span is not proof of a real Retry button; exercise a one-shot IndexedDB put error. A genuine 60s E2E requires `test.setTimeout(120_000)`, not the default 30s.
- **No false promises:** Existing persistence busy gate **drops** input; ticks dirty a city immediately after successful save; native Cmd+Q may bypass window close. Guard high-risk interactions and state limitations accurately.
